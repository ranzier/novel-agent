# 中文网文去 AI 腔局部改写模型：选型与数据集建设决策报告

> 文档性质：本地讨论总结与第一版实施依据  
> 更新时间：2026-09-08  
> 适用项目：`novel-agent` 章节生成后的局部风格编辑流程

## 1. 项目背景

当前小说 Agent 已经通过写作提示词约束模型减少模板化表达，但长篇章节中仍不可避免地残留少量 AI 腔，例如：

- 空泛、抽象的心理总结；
- 重复动作和无效动作分解；
- 机械转折与模板化承接；
- 对已经表现出来的情绪或事实再次解释；
- 不自然的对白、对称句和段落收尾；
- 句式过于整齐、抽象名词堆叠或缺乏人物口吻。

一篇约 3000 字的章节通常并非整体质量低下，而是只有约 30% 的内容可能需要轻微调整，其余约 70% 应保持不变。因此，本项目不打算再训练一个完整的小说创作模型，而是训练一个职责狭窄的**中文网文局部编辑器**。

它接收完整句子或段落，只做最小必要改写：

1. 消除明显 AI 腔；
2. 保持原意、事实和剧情不变；
3. 不续写、不扩写，不替作者推进情节；
4. 原文已经自然时，逐字原样返回；
5. 输出可以直接替换原文，不包含分析和解释。

最终目标不是让小模型在文学创作能力上全面超过前沿大模型，而是让它以更低成本、更低延迟、更稳定的行为，承担大多数常规段落的批量编辑任务。

## 2. 模型选型过程

### 2.1 硬件与任务约束

已确定的运行环境为魔搭平台 GPU Notebook，GPU 是 A10，可用显存约 22 GB。任务具有以下特点：

- 输入主要是中文网文段落，而非超长上下文；
- 输出通常与输入长度接近；
- 重点是理解约束并完成局部编辑，不是生成整章；
- 需要低成本批量推理；
- 模型规模希望在 7B 左右；
- 单卡显存不适合做 7B/8B 全参数微调。

因此，模型范围被收敛到中文能力较强、支持指令微调、可在单张 A10 上进行 4-bit QLoRA 的 7B～8B 稠密模型。

### 2.2 比较过的候选模型

| 候选模型 | 优点 | 顾虑 | 讨论结论 |
|---|---|---|---|
| Qwen2.5-7B-Instruct | 中文稳定；指令模板和工具链成熟；没有额外的思考输出管理；适合做稳健基线 | 相比新一代模型，上下文理解和多约束遵循上限可能略低 | 适合作为基线或快速验证数据管线 |
| Qwen3-8B | 中文语义能力更强；前后文、人物语气和复杂约束理解更好；8B 仍可在 A10 上做 QLoRA | 需要明确使用非思考模式；模型稍大；能力强也可能导致过度改写 | 最终选定为第一版基础模型 |
| DeepSeek-R1-Distill-Qwen-7B | 中文和推理能力较强，规模符合要求 | 目标偏推理；容易分析、解释或扩大修改范围；与“短输出、最小编辑”任务不完全匹配 | 可作为实验对照，不作为第一选择 |
| DeepSeek-V3 / R1 等完整模型 | 综合能力强 | 模型规模远超单张 A10 的本地微调能力 | 不进入本次单卡微调范围 |

### 2.3 最终模型决策

第一版最终选用：

```text
基础模型：Qwen/Qwen3-8B
模型类型：经过后训练、具备指令遵循能力的模型，不使用 Base 版本
训练方式：4-bit QLoRA
训练 GPU：A10，约 22 GB 显存
训练/推理模式：非思考模式
数据框架：LlamaFactory Alpaca 格式
运行环境：ModelScope/魔搭 GPU Notebook
```

Qwen3-8B 的主要选型优势是：

- 更好地理解一个段落内部的指代、递进、因果和人物语气；
- 更容易同时遵循“去 AI 腔、最少修改、事实不变、自然时不改”等复合约束；
- 8B 规模仍能通过 4-bit QLoRA 适配 A10；
- 后续可以复用同一数据规范测试更大的 Qwen3 模型；
- 中文生态、ModelScope 和 LlamaFactory 支持相对成熟。

Qwen3 支持思考与非思考行为，但该任务不需要思维链。训练标签中不能出现 `<think>`，推理时也必须关闭 thinking，只输出最终文本。

## 3. 为什么仍然值得训练小模型

先进大模型使用强提示词，也可能达到接近的单段改写效果。因此，小模型的价值不定义为“每句话都比大模型写得好”，而定义为：

- **成本**：适合持续、大批量处理章节；
- **延迟与吞吐**：可批量处理多个候选段落，避免远程 API 限流；
- **稳定性**：把“不解释、不扩写、原文自然时不改”等行为固化为默认能力；
- **风格一致性**：长期学习同一套人工编辑偏好；
- **隐私与可控性**：未发表小说可以在自有环境运行；
- **大小模型路由**：普通段落由小模型处理，复杂或高风险段落再交给先进大模型。

是否值得投入最终应通过固定测试集验证。只要小模型在自然度接近先进模型的同时，事实保持率不低、成本和延迟明显更优，就具有生产价值。若实际章节处理量很小，直接使用先进模型 API 可能更经济。

## 4. 模型职责与硬边界

模型只允许修改语言表达，不允许修改叙事事实。固定约束包括：

- 不新增、遗漏或改变剧情事实；
- 不改变人物关系、人物身份和对白归属；
- 不改变人名、地名、势力、境界、功法和道具；
- 不改变数字、日期、时间、距离、金额和数量；
- 不改变因果关系、肯定/否定关系和叙事视角；
- 不续写、不扩写、不补充原文没有的动作或心理；
- 不输出解释、候选方案、修改说明或思维链；
- 仅在确有必要时修改，原文自然时保持原样；
- 输出必须能够直接替换输入原文。

需要特别强调：把心理描写改成动作并不天然安全。如果原文没有“握刀”“推门”等事实，编辑模型不能为了让文字更具象而自行增加这些动作。

## 5. 训练与推理消息结构

### 5.1 LlamaFactory Alpaca 字段映射

本项目采用 Alpaca 格式：

```text
system      → 模型的 system message
instruction → user message 的固定任务前缀
input       → user message 中的待改写文本
output      → assistant 的标准答案
```

LlamaFactory 会将 `instruction` 与 `input` 拼接为用户提示。因此，`instruction` 不是一种独立的聊天角色。

### 5.2 最终固定提示词

建议第一版使用固定的 `system` 和固定的通用 `instruction`，减少无意义的提示词分布差异。

```json
{
  "system": "你是中文网络小说局部编辑器。仅修改语言表达，不得新增、遗漏或改变任何事实信息，包括剧情、人物关系、专名、数字、时间、地点、境界、道具、因果关系、叙事视角和对白归属。不得续写、扩写或解释。原文自然时必须保持原样。只输出可以直接替换原文的最终文本。",
  "instruction": "请对以下文本进行最小必要的去AI腔改写；仅在确有必要时修改，原文自然则保持原样。",
  "input": "待处理的完整句子或段落",
  "output": "人工确认后的最终文本，或与 input 完全相同的原文"
}
```

之前讨论过“去除空泛心理”“减少机械转折”“让对白更自然”等多种 instruction。第一版不建议把它们随机写入每条训练样本，因为线上推理只会使用一个通用指令。它们更适合作为不进入模型输入的 `issue_tags`，用于数据统计、抽样和评测。只有将来线上也能稳定识别问题类型并传入对应指令时，才应训练多种受控 instruction。

### 5.3 训练与推理必须一致

“一致”不是要求训练和推理出现相同的原文，而是要求模型看到相同的提示结构：

```text
固定 system
+ 固定 instruction
+ 新的待处理 input
```

程序可以对调用者只暴露 `rewrite(text)`，但内部仍需自动添加固定的 system 和 instruction。不能在训练时提供 instruction，部署时却只发送裸原文。

## 6. 改写单位与章节分块

### 6.1 默认使用完整段落

最终决定采用“段落优先、句子例外”的策略：

- 默认一次输入一个完整段落；
- 如果一个段落只有一句，它自然就是句子级样本；
- 只有当某一句语义独立、问题明确且改动不影响段落节奏时，才单句处理；
- 多句共同构成动作、心理过程或一轮对白时，必须整段处理；
- 超长段落按完整句群拆分，不能按固定字符数从句中截断；
- 场景用于理解结构和设定边界，不直接作为整块重写单位。

采用段落作为默认单位，是为了减少以下风险：

- 不理解“他、她、这件事”等指代；
- 改写后与前后句口吻不一致；
- 破坏递进、转折和节奏；
- 拆散对白与说话人的动作；
- 把有意设计的重复或短句停顿误判成 AI 腔。

### 6.2 实际章节分析

讨论中分析了 [第 20 章《不更乡啬夫》](../books/大秦我在岭南种田称霸/chapters/ch0020.md)。该章通过 `---` 形成田头接令、乡署授职、去职余波和门外密谈等场景边界。得到的原则是：

- `---` 是硬场景边界，不跨场景合并输入；
- 问题和回答、对白和动作、授职宣告和人物反应不能机械拆开；
- “李恒接令”“不更。乡啬夫。”“根，得扎得更深”等关键节奏句默认保留或人工复核；
- 段落级重写后必须按原顺序、原分隔符拼回章节；
- 不能让模型输出整章，否则大部分本来不需要修改的文本会被重新生成。

### 6.3 是否加入前后文

第一版可以采用最简单的纯目标段落输入：

```text
input = 待改写的完整段落
```

如果未来发现指代或语气错误明显，再升级为：

```text
【只读前文】
...
【目标段落】
...
【只读后文】
...
```

一旦升级，训练数据也必须采用同样结构，`output` 仍只包含目标段落。不能训练时只有目标段落、推理时突然加入大段前后文，并期待行为完全稳定。第一版与上下文版应作为两个明确的数据版本管理。

## 7. 数据集建设方案

### 7.1 数据来源

首批数据直接来自现有 Agent 生成的章节：

```text
books/<书名>/chapters/chXXXX.md
```

处理流程为：

```text
读取章节
→ 去除 Markdown 章节标题和场景分隔符
→ 按完整段落抽取
→ 保留书名、章节号、段落序号等元数据
→ 人工判断 keep / rewrite / reject
→ 人工完成最小改写
→ 自动质检与人工复核
→ 导出 Alpaca 训练文件
```

### 7.2 原始标注层与训练导出层分离

不应直接手工维护最终 Alpaca 文件。建议先建立包含完整元数据的标注文件：

```json
{
  "id": "book_slug-ch0020-p0011",
  "book": "大秦我在岭南种田称霸",
  "chapter": 20,
  "paragraph_index": 11,
  "source": "AI 生成的原段落",
  "target": "人工确认的最终段落",
  "decision": "rewrite",
  "issue_tags": ["解释性总结", "空泛心理"],
  "protected_terms": ["李恒", "赵佗", "不更", "乡啬夫"],
  "review_status": "approved",
  "reviewer": "editor_01"
}
```

字段含义：

- `rewrite`：原文需要修改，`target` 是人工最终版本；
- `keep`：原文自然，`target` 必须与 `source` 完全相同；
- `reject`：样本有歧义、上下文不足或候选改写改变事实，不进入普通 SFT；
- `issue_tags`：只用于分析，不放进第一版模型输入；
- `protected_terms`：用于自动质检和推理回退。

只有 `approved` 数据才转换成最终 Alpaca 文件。标注元数据应单独保存，以便以后追溯、重审和构建偏好数据。

### 7.3 数据比例不能脱离推理架构

讨论初期给出过“70% rewrite + 30% keep”的通用建议，但在明确真实章节只有约 30% 内容需要修改后，必须区分两种架构：

#### 方案 A：所有段落都经过同一个改写模型

训练分布应该尽量贴近真实推理分布：

```text
keep：约 60%～70%
rewrite：约 30%～40%
```

比例最好按字符数或 token 数统计，而不只是按样本条数统计。该方案实现简单，但模型对大量自然段落仍有误改风险。

#### 方案 B：检测器 + 改写器（推荐）

```text
章节段落
→ 检测器判断 keep / rewrite / review
→ 只把高置信度 rewrite 送给改写模型
```

此时改写器数据可以以正样本为主：

```text
rewrite：约 70%～80%
困难 keep：约 20%～30%
```

“困难 keep”是看起来可能有模板感、但人工仍认为无需修改的边界样本，不是随便填入的简单自然句。检测器的测试集必须保持真实的 70% keep / 30% rewrite 分布，以避免指标失真。

项目长期推荐方案 B；首个冒烟版本可以暂时使用方案 A，但需要提高 keep 比例并严格回退。

### 7.4 长度与内容分布

训练数据应接近未来真实调用分布，而不是为了制作方便大量收集孤立短句。建议按实际章节统计后定桶，初步可划分：

```text
短文本：20～80 字
中等句群：80～200 字
完整段落：200～600 字
```

此前讨论过“70% 单句、30% 段落”，但最终推理已经决定段落优先，因此该比例不应被机械采用。更合理的方法是先统计 20～50 章的真实段落长度和单句段落占比，再按真实分布抽样。

内容必须覆盖：

- 叙述、对白、动作、心理、环境和转场；
- 轻微改写、明显改写和原样保留；
- 多角色场景、对白归属和连续动作；
- 人名、别名、地名、势力、境界、道具和功法；
- 数字、日期、金额、距离等高风险事实；
- 开篇、推进、冲突、高潮和章节收尾；
- 不同句长、不同情绪强度和不同段落节奏。

首批数据应优先来自真实生产章节，不大量混入新闻、论文、广告或普通作文润色数据，以免模型学成正式改写器而不是网文局部编辑器。

### 7.5 数据规模规划

采取分阶段策略：

1. **标注规范试运行：约 100～200 条**  
   验证标注人员对“最小必要改写”和“事实不变”的理解是否一致。
2. **冒烟训练：约 500～1000 条**  
   验证格式、训练链路、keep 能力和事实保持能力。
3. **第一版正式训练：约 3000～5000 条**  
   覆盖主要 AI 腔类型、文本长度和高风险事实。
4. **生产迭代：8000～10000 条以上**  
   通过真实失败案例持续扩充，而不是单纯批量生成同质数据。

数据质量优先于数量。由先进模型生成的候选改写只能作为人工编辑草稿，不能未经审核直接作为标准答案，否则小模型只会继承另一种 AI 腔。

## 8. 标注规范

人工标注时遵守以下原则：

1. 只修复明确存在的问题；
2. 能改一句就不重写整段，能改少量词就不替换全部表达；
3. 不追求华丽、文学化或信息更完整；
4. 不新增动作、心理、环境、判断或后续剧情；
5. 不删除看似冗余但承担事实、语气或节奏作用的内容；
6. 保持人物口吻、叙事视角、时间顺序和对白归属；
7. 保留所有专名、数字、否定关系和因果关系；
8. 原文自然时选择 `keep`，并保证 `source == target`；
9. 信息不足、修改风险高或无法判定时选择 `reject`，不勉强构造答案；
10. 输出不得包含“改写结果”“修改说明”等前缀。

常用 `issue_tags` 可以限制在一个稳定词表中：

```text
空泛心理
解释性复述
重复动作
机械转折
模板化收尾
过度对称/排比
抽象名词堆叠
对白不自然
句子节奏单一
无效环境描写
其他
```

标签不决定必须怎样改，只用于统计覆盖度、发现数据偏差和建立分层测试集。

## 9. 数据质量控制

### 9.1 自动检查

每条样本进入训练集前至少检查：

- `source`、`target` 非空；
- `keep` 样本严格满足 `source == target`；
- 输出不含 `<think>`、解释、标题或多个候选；
- 人名、专名、数字、时间、境界、道具是否保留；
- 否定词和肯定/否定关系是否改变；
- 是否新增疑似人名、地点或道具；
- 文本是否是完整句子、句群或段落；
- 输出长度是否异常缩短或膨胀；
- 是否存在完全重复和近似重复样本；
- 标点、引号和对白格式是否完整。

长度比可以先用宽松阈值进行预警，例如：

```text
0.6 ≤ target 字符数 / source 字符数 ≤ 1.4
```

超出阈值不自动删除，但必须人工复核。

### 9.2 人工复核

至少抽取 10%～20% 样本做第二人复核。重点关注“文字看起来更自然，但事实已经变化”的隐蔽错误。高风险样本和自动检查告警样本应全部复核。

### 9.3 数据集切分

不能随机把同一章节的相邻段落分别放入训练集和验证集。推荐：

```text
train：80%
validation：10%
test：10%
```

按整章或整本书切分，测试集最好包含训练中完全未出现过的书。测试集确定后冻结，不再参与提示词调整和训练数据修改。

## 10. 训练配置初稿

针对 A10 约 22 GB 显存，初始建议：

```text
训练方式：4-bit QLoRA，NF4
per_device_train_batch_size：1
gradient_accumulation_steps：16
max_length：先从 1024 开始，显存充足再升至 1536
num_train_epochs：2
learning_rate：1e-4
lora_rank：16
lora_alpha：32
lora_dropout：0.05
gradient_checkpointing：开启
```

具体参数应以当前 LlamaFactory、Transformers 和 Qwen3 模板支持为准。先用 500～1000 条数据跑通链路和显存测试，再开始正式训练。

## 11. 生产推理架构

### 11.1 推荐的两阶段流程

```text
章节初稿
→ 保留标题和场景分隔符，按完整段落解析
→ 检测器判断 keep / rewrite / review
→ keep：直接保留原文
→ rewrite：送入 Qwen3-8B 微调模型
→ review：暂时保留或交给先进大模型/人工
→ 专名、数字、否定关系、长度和格式校验
→ 校验失败：恢复原文
→ 按原顺序拼回章节
→ 执行整章一致性审校
→ 保存、提取摘要并更新世界状态
```

这与项目现有的记忆和一致性原则一致：局部风格改写应发生在摘要/世界状态最终提交之前，避免后处理改变正文而状态仍基于旧文本。

### 11.2 大小模型路由

建议按风险分工：

```text
普通叙述、重复动作、空泛心理、机械转折
→ 微调小模型

复杂情绪、关键对白、战斗规则、伏笔、身份揭示
→ 先进大模型或人工复核

授职、境界变化、数字密集、章节钩子
→ 默认保留，或高风险人工审核
```

小模型负责规模，先进模型负责难例。先进模型还可以生成候选改写，经人工确认后回流为下一轮训练数据。

## 12. 评测方案

不能只凭“读起来是否更顺”选择 checkpoint。固定测试集至少比较：

```text
原始章节
未微调 Qwen3-8B
微调 Qwen3-8B
先进大模型改写
```

核心指标：

| 指标 | 含义 | 优先级 |
|---|---|---:|
| 事实保持率 | 人名、数字、设定、因果、否定关系是否不变 | 最高，硬门槛 |
| 原样保留准确率 | 自然段落是否保持不变 | 高 |
| 改写精确率 | 被改的段落中，人工认可确有必要且有所改善的比例 | 高 |
| 自然度胜率 | 改写版相对原文是否更自然 | 高 |
| 过度改写率 | 是否在不必要处大幅重写 | 高 |
| 改写覆盖率 | 应改内容中实际被改善的比例 | 中 |
| 平均改动率 | 输出相对输入的字符/词级变化幅度 | 中 |
| 格式合规率 | 是否只输出最终文本、无解释和 `<think>` | 高 |
| 每万字成本与延迟 | 与先进模型 API 比较部署价值 | 中 |
| 多次输出稳定性 | 相同输入多次推理是否波动 | 中 |

本任务应优先追求改写精确率和事实安全，而非强行提高覆盖率：漏改一处通常可以接受，改错一处剧情事实不能接受。

## 13. 第一版执行计划

### 阶段一：固定规范

- 冻结 system、instruction 和 Alpaca 导出格式；
- 固定段落级输入，暂不混入另一种上下文格式；
- 固定 `decision`、`issue_tags` 和审核状态词表；
- 编写标注示例和反例。

### 阶段二：抽取与标注

- 扫描 `books/*/chapters/chXXXX.md`；
- 按章节和段落生成候选清单；
- 先人工标注 100～200 条，检查规范是否可执行；
- 建立 rewrite、keep 和 reject 样本；
- 从角色库、设定和正文提取保护项。

### 阶段三：质检与导出

- 执行专名、数字、长度、格式和重复检查；
- 对告警样本及 10%～20% 普通样本二审；
- 按章节或书籍切分 train/validation/test；
- 导出 LlamaFactory Alpaca JSON；
- 验证 JSON 可加载及提示拼接结果。

### 阶段四：冒烟训练

- 用 500～1000 条数据完成第一次 QLoRA；
- 检查是否只输出正文、是否学会 keep、是否改变事实；
- 不以训练 loss 作为唯一依据；
- 根据失败样本调整数据，而不是立即堆数量。

### 阶段五：正式版本与迭代

- 扩充到 3000～5000 条高质量样本；
- 在固定测试集上与先进模型和未微调模型对比；
- 收集漏改、过改和事实改变案例；
- 将人工确认的生产失败案例回流到下一版数据集；
- 若单阶段模型误改率仍高，再实现独立检测器。

## 14. 当前最终决策摘要

```text
基础模型：Qwen/Qwen3-8B
硬件：A10，约 22 GB
训练：4-bit QLoRA，非思考模式
框架：魔搭环境 + LlamaFactory Alpaca 数据
任务：中文网文句子/段落的最小必要去 AI 腔编辑
默认输入单位：完整段落；语义独立时可单句处理
system：固定硬约束
instruction：固定短任务指令
input：完整待改写文本
output：人工确认的改写结果，或完全相同的原文
数据来源：现有 AI 生成章节
长期推理架构：检测器 + 改写器 + 自动校验 + 失败回退
质量原则：只改表达、尽量少改、事实不变、自然时不改
```

本项目成功的关键不在于把所有章节都重新润色一遍，而在于准确识别少量需要修改的内容，并让模型在不破坏任何叙事事实的前提下稳定完成局部编辑。
