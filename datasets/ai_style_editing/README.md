# 中文网络小说去 AI 腔数据集

本文档规定本目录数据集的采集、标注、质检和导出约定。目标是从
`books/*/chapters/chXXXX.md` 的已有章节中，先做一轮可复核的 1000 条小数据，
再用固定测试集迭代扩大到正式数据。当前目录是按用户要求导出的 **draft Alpaca
数据**：三份 split 文件共 1000 条，但尚未逐条人工确认，不能直接当作金标准训练集。
人工复核完成后，才可将确认后的记录另存为正式训练文件并把状态改为可训练。

## 1. 导出格式

`train.json`、`val.json`、`test.json` 都是 UTF-8 编码的 JSON 数组。每条记录只
包含下面四个字段，字段名和含义固定，适配 LlamaFactory Alpaca 格式：

```json
{
  "system": "你是中文网络小说局部编辑器。仅修改语言表达，不得新增、遗漏或改变任何事实信息，包括剧情、人物关系、专名、数字、时间、地点、境界、道具、因果关系和对白归属。不得续写、扩写或解释。只输出可以直接替换原文的最终文本。",
  "instruction": "请对以下文本进行最小必要的去AI腔改写；仅在确有必要时修改，原文自然则保持原样。",
  "input": "原始完整句子或段落",
  "output": "人工确认后可直接替换原文的最终文本（当前导出为待审草稿）"
}
```

`system` 和 `instruction` 是常量，不能按书、章节或标签改写。字符串中不放
章节标题、书名、来源路径、标注理由或 `<think>`。`output` 必须是正文本身，不能
带“改写结果：”“说明：”等前缀。

采集阶段可使用一个不导出的内部标注对象保存审计信息，例如：

```json
{
  "id": "大秦我在岭南种田称霸/ch0001/p003",
  "book": "大秦我在岭南种田称霸",
  "chapter": 1,
  "paragraph": 3,
  "input": "...",
  "output": "...",
  "label": "rewrite",
  "issue_types": ["机械转折"],
  "review_status": "review_required",
  "source_path": "books/大秦我在岭南种田称霸/chapters/ch0001.md",
  "split": "train"
}
```

内部记录用于追溯和复查，不能直接喂给训练器。`manifest.json` 可以保存文件
版本、源章节清单、每个 split 的样本数和 SHA-256；不要把完整原文之外的隐私
或临时模型输出混入 Alpaca 文件。

自动抽取或自动改写的中间产物可放在 `candidates.jsonl`（或同类明确带 `draft`
的文件名）中，`review_status` 使用 `machine_draft` 或 `review_required`。本次
为了满足交付接口，待审草稿仍导出为 `train.json`、`val.json`、`test.json`；这些
文件名只表示 split，不表示已经人工确认。`keep` 也需要人工确认文本确实自然，
不能仅因机器未命中规则就自动视为金标。

## 2. 章节抽取

1. 只扫描 `books/*/chapters/ch[0-9][0-9][0-9][0-9].md`，按书名和章节号的
   数值顺序排序；跳过 `state.json`、摘要、向量和非章节 Markdown。
2. 用 UTF-8 读取，去掉 BOM，统一 `CRLF` 为 `LF`。只清理段落两端空白，不能
   在正文中做全角半角、标点或同义词归一化，因为这会改变可学习的原文。
3. 删除首个匹配 `^\s*#\s*第\s*\d+\s*章[^\n]*$` 的 Markdown 章节标题，
   以及正文中重复出现的同章标题（例如 `【第 7 章　粮道之争】`）。删除独立
   的 `---`、`***`、`___` 分隔线和卷终元文本（如 `*第三卷　终*`、
   `《书名》第一卷《卷名》终。`）。这些标题、卷名和分隔线绝不成为样本；若
   卷终标记与正文粘在同一段，先剥除标记，再保留前面的完整正文句。
4. 以连续空行分段；一个样本优先对应一个完整段落，不跨段拼接。不要把对白
   强行拆成句子；当前首版生成器只保留长度为 15--220 个字符且以句末标点
   结束的完整段落，短句和超长段落需在人工阶段单独处理，不能为了凑数量截断句子。
5. 过滤明显不完整或非正文块：空段、残留 Markdown 标题/代码围栏、卷终/卷名、
   只含装饰符号的段落和长度异常的整章块。
6. 保留 `book/chapter/paragraph` 来源坐标，以及去除标题后的原始 `input`。
   若段落末尾有换行，内部记录可统一去掉，导出时 `input` 和 `output` 不带额外
   首尾空白。

当前仓库有 36 个章节，段落数量足以筛出 1000 条；应先统计候选数和每章分布，
再决定是否放宽长度阈值，不要重复复制同一段落。

## 3. 标注规则

每个候选只能有一个决定：`rewrite`、`keep` 或 `reject`。`reject` 不导出；当前
生成器只在 manifest 中统计被拒数量，正式人工标注时应另外保存每条 reject 的来源
和原因，便于修订规范。

### `keep`

- 原文已经自然、清楚，或修改只会变成个人偏好；
- `output` 必须与 `input` 完全相同（除内部统一的首尾空白处理）；
- 不得为了满足比例而对自然段落做无意义替换。

### `rewrite`

- 原文有明确、可指出的语言问题，且只做最小必要修改；
- 只改变措辞、句法、重复和节奏，不改变事实、视角、时态或对白归属；
- `output` 至少有一处实际变化，读起来可以直接替换原文；
- 不新增解释、总结、动作、心理、因果、环境细节或下一段剧情；
- 建议记录一个或多个受控问题类型：`空泛心理`、`机械转折`、`重复动作`、
  `冗余程度副词`、`冗余表达`、`重复表达`、`时间表达`、`句式调整`、
  `同义替换`、`过度解释`。脚本还会记录格式清理类 `标点混用`、`引号规范`；
  这两类只修正格式，不应与去 AI 腔效果混为一谈。

### `reject`

出现下列任一情况就拒绝，而不是勉强修成样本：原文不是完整句/段；标题、分隔
线或元文本；无法判断事实；改写引入或删除剧情信息；人物、专名、数字、时间、
地点、境界、道具、因果或对白归属变化；输出带解释/标题/`<think>`；语法更差；
与已有样本重复或只是模板替换；需要大幅重写、续写或扩写。

“原文疑似 AI 生成”本身不是 `rewrite` 理由，必须能指出具体语言问题。机器
检测器的高分只能产生候选，不能直接决定标签。

## 4. 事实与语言质检

质检分为自动预检和人工复核，自动检查失败的记录直接进入 `reject` 或人工待
复核队列，不自动篡改输出。

自动预检至少包括：

- 四个字段存在且都是非空字符串；`system`、`instruction` 与常量逐字一致；
- JSON 可解析、UTF-8 合法、无 NaN/注释/尾随逗号；记录 ID 唯一；
- `input`、`output` 无首尾空白、Markdown 标题、代码围栏、`<think>` 或解释
  前缀；输出不以“改写结果”“以下是”等元话语开头；
- `keep`（若保留内部标签）满足 `input == output`，`rewrite` 满足 `input != output`；
- 数字、日期、时间、计量单位、中文数字和百分比等 token 的多重集合一致；
- 书名、人物名、地点、境界、道具等来自 `bible.json`、`characters.json` 或
  人工维护词表的专名未丢失，也没有凭空增加；
- 引号/对白标记数量和配对关系合理，不能把叙述改成对白或改变说话人；
- 改写长度和字符级 diff 比例仅作为告警（例如变更比例超过 45% 或长度超过
  原文 1.5 倍），当前告警汇总在 `manifest.json`，最终由人工决定，短句不因固定
  阈值误杀；
- 归一化后的 `input` 不与其他 split 重复；高度相似的段落按来源章节成组，
  不得一条进 train、近重复另一条进 val/test。

人工复核时并排查看原文及其前后各一段，逐项确认：

1. 人名、专名、数字、时间、地点、境界、道具和人物关系没有变化；
2. 没有新增、遗漏或调换动作、心理、剧情、因果和对白归属；
3. 只修正明确的 AI 腔，原文自然时选择 `keep`；
4. 输出读起来通顺，且能不加任何连接文字直接替换原文；
5. 失败样本写明原因，供下一轮标注规范修订。

机器改写（规则替换或 LLM）只能作为待审草稿。当前 `train`/`val`/`test` 文件
因此全部标记为 `review_required`，不能声称是“人工改写数据”；未经人工逐条确认
不得用于正式训练。

## 5. 划分和数量

先按完整章节分配 split，再在各 split 内选样本；禁止先打散段落后随机切分。这样
可避免同一章节的上下文近重复同时出现在训练和评估中，并保留测试集独立性。

当前 36 章可采用下面的可复现时间块（章节号为 1-based）：

| 书籍 | train | val | test |
| --- | --- | --- | --- |
| `1642:南明北伐录` | 1--4 | 5 | 6 |
| `大秦我在岭南种田称霸` | 1--20 | 21--25 | 26--30 |

两本书都在三个 split 中出现，测试集使用每本书较后的整章，既不随机打散，也不
把同章段落泄漏到其他 split。若章节数量变化，保留“按书籍、按连续章节块”的
原则并在 `manifest.json` 更新映射；不要静默改动既有 test。

第一版目标为 1000 条，导出为 `train/val/test = 800/100/100`。当前每个 split
保留约 35% 的 `keep`（train/val/test 为 280/35/35），其余是规则生成、待人工
确认的 `rewrite` 草稿。脚本按章节轮询平衡采样，但暂未设置每章硬上限；正式标注
时应再按问题类型、段落长度、对白/叙述比例做多样性抽样。先完成 test 并保存校验和，
后续迭代只可新增或修订 train/val；test 的原文、输出、split 和顺序冻结。生成器
是全量重建脚本，人工修改后不要直接覆盖运行；应先保留人工复核结果，或实现单独
的 review overlay，再重新导出。

推荐的确定性流程是：章节分组 → 自动预检 → 人工标注 → 去重 → 按 split 配额
采样 → 再次校验 → 导出。固定随机种子只用于同一 split 内抽样，不能跨 split
移动样本来凑数量。

## 6. 导出前清单

- 三个 JSON 都能用标准 JSON 解析器读取，数组总数为 1000，分配为 800/100/100；
- 每条只含 `system`、`instruction`、`input`、`output` 四个字段，顺序固定；
- `input` 是完整句子或段落，已去掉章节标题和分隔线；
- `output` 是待人工确认的替换文本草稿，无解释、标题、`<think>` 或续写；
- keep 比例和 rewrite 问题类型分布在记录中可追溯；
- 事实 token、专名、对白归属检查通过，重复和低质量样本已删除；
- `manifest.json` 记录源文件校验和、章节 split、样本计数、生成时间和规范版本；
- test 文件已冻结，之后的标注修订不会读取其结果来反向修改 test。
